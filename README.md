## Моя личная Фудзияма: SQL Challenge 🌋💎

Проект по проектированию комплексных SQL-запросов, анализу данных и автоматизации выгрузок для обработки структурированных массивов. В репозитории аккумулированы скрипты для решения сложных аналитических и продуктовых бизнес-кейсов.

---

### 🛠️ Что внутри (Технический стек и кейсы)

*   **Построение сквозной аналитики:** Применение сложных соединений `LEFT JOIN`, `RIGHT JOIN` и `FULL JOIN` для сохранения пустых категорий, агрегации данных и минимизации потерь при слиянии таблиц.
*   **Глубокая декомпозиция данных:** Проектирование многоуровневых вложенных выборок и сложных расчетов с использованием нескольких подзапросов в рамках одного оператора `SELECT`.
*   **Анализ связанных структур:** Написание коррелированных (взаимосвязанных) подзапросов, двойных выборок и многомерных группировок данных (`GROUP BY`, `HAVING`).
*   **Оптимизация логики:** Использование сессионных переменных, ранжирования данных и фильтрации аномалий в сырых выгрузках.

---

### 🎯 Примеры реализации бизнес-логики

#### 1. Использование LEFT JOIN для сохранения структуры данных
*Позволяет не терять категории/товары с нулевыми продажами при построении итоговых отчетов:*
```sql
SELECT 
    c.category_name,
    COUNT(p.product_id) AS total_products,
    COALESCE(SUM(o.amount), 0) AS total_sales
FROM categories c
LEFT JOIN products p ON c.category_id = p.category_id
LEFT JOIN orders o ON p.product_id = o.product_id
GROUP BY c.category_name;
```

#### 2. Комплексный расчет через вложенные подзапросы
*Вычисление отклонений индивидуальных метрик от средних значений по сегментам без просадки производительности базы:*
```sql
SELECT 
    employee_id,
    department_id,
    salary,
    (SELECT AVG(salary) FROM employees e2 WHERE e2.department_id = e1.department_id) AS dept_avg_salary
FROM employees e1
WHERE salary > (SELECT AVG(salary) FROM employees);
```
